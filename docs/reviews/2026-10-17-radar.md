# FMI's replacement rain rate

Source checks for #133, 2026-10-17, starting at main `87a9b07`. No planner or sheet design changes.

## Source and download format

FMI's [2026 radar changes](https://www.ilmatieteenlaitos.fi/avoin-data-saatutkat) replace `Radar:suomi_rr_eureffin` with `Radar:radar_finland_cappi_rate`. The [download manual](https://en.ilmatieteenlaitos.fi/open-data-manual-radar-data) says the old layers go away in November 2026, and counts GetMap requests in `image/geotiff` format as Download Service use. Styled view tiles are for evaluation only; Polku requests GeoTIFFs and draws its own map image.

The replacement's capabilities identify its measurements as mm/h, with 5-minute scans, altitude 600 m and the `finradfast` domain by default. Both WMS and the public AWS bucket returned `Access-Control-Allow-Origin: *` to a localhost Origin.

The retained reflectivity layer has the same stretching problem: its default raster byte at the sampled centre was 149, while native GetFeatureInfo reported 5 dBZ. Applying the old `byte * 0.5 - 32` rule would give 42.5 dBZ and greatly exaggerate rainfall. Both layers therefore use fixed encoding. The fallback's colour-path levels are -32, -20, -10, 0, 10, 30 and 95 dBZ; its sampled fixed colour `#7fff00` decodes to 4.98 dBZ. Marshall–Palmer conversion and the existing 0.3 mm/h clutter threshold are applied only after recovering dBZ.

The default `styles=raster` response is one uncompressed 8-bit band. At the same time and resolution, overlapping pixels in different bounding boxes have different byte values. These are display values, not a fixed scale of rainfall. WCS still returned `Service WCS is disabled`. The sampled current-day AWS `finrad` listing contained reflectivity and `finradfast` contained accumulations; neither listing supplied the current rain-rate product.

## Fixed encoding

`radar.js` supplies its own [SLD ColorMap](https://docs.geoserver.org/3.0.x/en/user/styling/sld/reference/rastersymbolizer/) with `extended="true"`, and requests nearest-neighbour sampling. Its fixed colour path encodes the physical quantity:

| mm/h | Encoding colour |
|---:|---|
| -1, 0 | `#000001` (dry; the negative padding keeps zero away from the palette's background slot) |
| 0.01 | `#0000ff` |
| 0.1 | `#00ffff` |
| 1 | `#00ff00` |
| 10 | `#ffff00` |
| 100 | `#ff0000` |
| 1000 | `#ff00ff` |

White is requested as the missing-coverage background, outside this path. Between entries the channel changes linearly, so inverting the colour recovers a measurement. Quantization is at most 1/255 of the relevant interval's span, before the primary rate is rounded to 0.01 mm/h. Trace rain below the existing 0.03 mm/h display threshold stays hidden. Rates above 100 mm/h keep their decoded amount but use the top map colour, as before.

The resulting GeoTIFF has one unsigned 16-bit palette band and uncompressed strips. **Its indexes are not measurements:** follow each index into tag 320's RGB colour table, then invert the fixed encoding. Do not assume the indexes are ordered by intensity or retain the same numbering. Unknown used colours, a missing palette, truncated strips or an unexpected pixel format fail the primary path instead of becoming rainfall. The existing reflectivity fallback remains; provider-wide back-off and rate limits are respected.

## Recorded checks

All comparisons used `2026-10-17T08:00:00Z`, EPSG:3067, one kilometre per pixel:

- Wide: bbox `300000,6700000,700000,7100000`, 400 × 400.
- Small: bbox `400000,6800000,500000,6900000`, 100 × 100.
- Coverage sample: bbox `-208000,6390000,1072000,7926000`, 128 × 154.
